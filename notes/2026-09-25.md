## Record Converter

An Elixir module called [`Record`](https://elixir.hexdocs.pm/Record.html) has been created to deal with
[Erlang records](https://www.erlang.org/doc/system/ref_man_records.html). Unfortunately, it seems
those generated records can't use name starting with an uppercase character. Probably because
the [macro generate a function](https://github.com/elixir-lang/elixir/blob/v1.20.4/lib/elixir/lib/record.ex#L262), and
I don't think function in Elixir can start with such letters. The problem is most of the records
used in the `public_key` module are starting with an uppercase letter!

```
== Compilation error in file lib/expki/keys.ex ==
** (SyntaxError) invalid syntax found on lib/expki/keys.ex:20:8:
    error: unexpected ( after alias T. Function names and identifiers in Elixir start with lowercase characters or underscore. For example:

        hello_world()
        _starting_with_underscore()
        numb3rs_are_allowed()
        may_finish_with_question_mark?()
        may_finish_with_exclamation_mark!()

    Unexpected token: (
    │
 20 │   def T() do
    │        ^
    │
    └─ lib/expki/keys.ex:20:8
    (elixir 1.19.5) lib/kernel/parallel_compiler.ex:529: anonymous fn/5 in Kernel.ParallelCompiler.spawn_workers/8
```

Let have a look on alternative solutions then:

* continue to use raw tuples, but this is not really stable and
  can break the implementation if some version of the module
  change a record (argument position for example)

* re-implement the `Record` Elixir module and try to find a way to
  support the record name with uppercase letters, but I don't think
  it will be possible to achieve that easily, because the `Record`
  module creates functions.

* generate a module for each record, exporting functions to check,
  match, convert the record in different formats. If we enable all
  records, it will be 157 new modules created. It also means macros
  are required somewhere to avoid code deduplication. It could also
  be a good idea to create struct and types.

I thinks the last solution is probably the easiest one to implement, 
and it will be the one used for now. The goal is to be able to
decode/encode minimal certificates, not to support all TLS
features.

```elixir
# a short example to generate tokens from erlang header
# file using Elixir and erlang preprocessor module (epp).
case :code.lib_dir(:public_key) of
  {:error, reason} -> {error, reason}
  path when is_list(path) ->
    path ++ '/include/public_key.hrl'
    |> :epp.parse_file([{:source_name, :pp}])
end
```

The module in charge to convert the record to struct has been
created. It uses a macro to import, making the creation of
each struct/modules easier. The idea:

```elixir
defmodule Expki.PublicKey.RecordName do
  use Expki.PublicKey, name: :RecordName
end
```

A wrapper for pem encoding can also be added automatically
when applying the macro by setting `pem: true`.

## Erlang Preprocessor Macros

When parsing Erlang source code, the first step is to apply
the macros from using `epp` (the erlang preprocessor). Not 
all data are exported though, for example, the macros themselves
(e.g. `-define()`) are not present in the final result. To fetch
this information, one should use the `epp:open/2` function and
hack a bit around. Let me explain that

```console
$ cat > t.erl << EOF
-module(t).
-export([t/0]).
-define(TEST_MACRO, 1).

t() -> ?TEST_MACRO.
EOF
```

When using `epp:parse_file`, all macros like `-ifdef`, `-include` or `-define` are
simply ignored. One can check that with the following code:

```console
> {ok, Parsed} = epp:parse_file("./t.erl").
{ok, [{attribute, ...]}}
```

To retrieve all macros (`-define`) from Erlang, one must
use `epp:open/2` and parse the whole file. Then, one must
[craft a special message](https://github.com/erlang/otp/blob/de741b771b0018d395c7d99eb985e26b426dc650/lib/stdlib/src/epp.erl#L1166) to retrieve the macros definitions.

```
> {ok, F} = epp:open("./t.erl", []).

> epp:parse_erl_form(F).
{ok, ...}

> epp:parse_erl_form(F).
{eof, ...}

> F ! {epp_request, self(), macro_defs}.

> flush().
Shell got {epp_reply,<0.101.0>, ...}
```

The format returned will look like that:

```erlang
{epp_reply,<0.101.0>,
           [{{atom,'FEATURE_ENABLED'},[{1,{['X'],[{atom,1,false}]}}]},
            {{atom,'FEATURE_AVAILABLE'},
             [{1,
               {['X'],
                [{'(',1},
                 {'(',1},
                 {var,1,'X'},
                 {')',1},
                 {'==',1},
                 {atom,1,maybe_expr},
                 {')',1}]}}]},
            {{atom,'OTP_RELEASE'},{none,[{integer,1,28}]}},
            {{atom,'MACHINE'},{none,[{atom,1,'BEAM'}]}},
            {{atom,'LINE'},{none,[{integer,1,1}]}},
            {{atom,'FILE'},{none,[{string,1,"_test/t.erl"}]}},
            {{atom,'MODULE'},{none,[{atom,1,t}]}},
            {{atom,'MODULE_STRING'},{none,[{string,1,"t"}]}},
            {{atom,'BASE_MODULE'},undefined},
            {{atom,'BASE_MODULE_STRING'},undefined},
            {{atom,'FUNCTION_ARITY'},undefined},
            {{atom,'FUNCTION_NAME'},undefined},
            {{atom,'BEAM'},{none,[{atom,1,true}]}},
            {{atom,'TEST'},[{none,{none,[{integer,2,1}]}}]}]}
```

As you can see, default macros are also present. The data-structure
returned is from another test module (not the one created above).

Before the opened file is using a raw `spawn/1` function call,
`sys:get_state/1` is not supported and will freeze the shell. The
only way right now is to really read the whole file, and then extract
the macros.

So, to generate and cleanup the macro from `public_key` module,
one will need to parse and then generate Elixir macros to include
them inside a function (or a module).
