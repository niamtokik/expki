## Erlang form to Erlang Term conversion

```elixir
  # erl_form converter
  def token({:dot, _}), do: ~c"."
  def token({x, _}) when is_atom(x), do: :erlang.atom_to_list(x)
  def token({:var, _, x}), do: :erlang.atom_to_list(x)
  def token({:char, _, c}), do: :io_lib.write_char(c)
  def token({:string, _, s}), do: :io_lib.write_string(s)
  def token({:atom, _, a}), do: :io_lib.write_atom(a)
  def token({_, _, x}), do: :io_lib.format("~w", [x])

  def tokens_to_charlist([], buffer) do
    # convert the buffer into
    expression = buffer
      |> Enum.reverse
      |> List.flatten

    with {:ok, tokens, _} <- :erl_scan.string(expression),
        {:ok, term} <- :erl_parse.parse_term(tokens)
    do
      {:ok, term}
    end
  end
  def tokens_to_charlist([token|tokens], buffer) do
    tokens_to_charlist(tokens, [token(token)|buffer])
  end
```

## Certificate Generation

This part is complex, because generating a certificate is not simply
sharing the public key, but also using X.509 format with ASN.1 defined
types. Those types are defined in many RFCs:

* [RFC 3279: Algorithms and Identifiers for the Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile](https://www.rfc-editor.org/info/rfc3279)
* [RFC 3280: Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile](https://www.rfc-editor.org/info/rfc3280)
* [RFC 4055: Additional Algorithms and Identifiers for RSA Cryptography for use in the Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile](https://www.rfc-editor.org/info/rfc4055/) 
* [RFC 8692: Internet X.509 Public Key Infrastructure: Additional Algorithm Identifiers for RSASSA-PSS and ECDSA Using SHAKEs](https://www.rfc-editor.org/info/rfc8692/)
* and many others...

The ANS.1 standardized keys/identifiers have been
mostly implemented in Erlang and defined as macros (the
reason why it was required to import them in some ways).
They got all an atom for identifier and returns a tuple
representing the ASN.1 object.

Because we just want to implement a subject of the 
certificate generation, we will cover only the required
fields and attributes.


```elixir
%TBSCertificate{
  version: integer(),
  serialNumber: integer(),
  signature: %TBSCertificate_signature{},
  rdnSequence: [],
  "Validitity": %Validity{},
}

```

  * [`signature`](https://www.rfc-editor.org/info/rfc5280/#section-4.1.2.3):

  * [`subject`](https://www.rfc-editor.org/info/rfc5280/#section-4.1.2.6)
